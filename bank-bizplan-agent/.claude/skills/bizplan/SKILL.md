# 신사업 기획서 작성

대상 아이디어: $ARGUMENTS

## 1. 준비

- 아이디어가 비어 있거나 한 줄로 모호하면, 사용자에게 **최대 3개**만 질문한다: 타깃 고객, 은행이 활용할 핵심 자산, 원하는 사업 형태(직접/자회사/제휴). 답이 없으면 합리적으로 가정하고 가정을 명시한 뒤 진행한다.
- `inputs/` 폴더에 관련 내부 자료가 있으면 먼저 읽는다.
- 프로젝트 폴더 `outputs/<YYYYMMDD>-<영문-슬러그>/`를 만든다.
- 문제 정의를 `00-brief.md`에 쓴다: 대상 고객, 문제, 해결 방식, 은행의 활용 자산, 가정.

## 2. 병렬 분석

아래 세 서브에이전트를 **한 번에 병렬로** 실행한다. 각각에 `00-brief.md` 경로와 프로젝트 폴더 경로를 넘긴다.

- `market-researcher` → `01-market.md`
- `regulation-reviewer` → `02-regulation.md`
- `financial-modeler` → `assumptions.json`, `03-financials-calc.md`, `03-financials.md`
  (재무 모델러에게는 시장 규모 추정을 스스로 보수적으로 가정하게 하고, 시장조사 결과가 나오면 3단계에서 보정한다.)

## 3. 정합성 확인

- 재무 가정(고객 수, 객단가)이 `01-market.md`의 SOM·벤치마크와 맞는지 확인한다. 어긋나면 `assumptions.json`을 고치고 `python3 tools/fin_model.py`를 다시 돌린다.
- 규제 판단이 **현행법상 불가**면 사용자에게 알리고, 사업 구조를 바꿀지(제휴·자회사·샌드박스) 물은 뒤 진행한다.

## 4. 반박 검토

`risk-critic`을 실행해 `04-risk.md`를 만든다. 지적 사항 중 기획으로 대응 가능한 것은 대응 방안을 마련한다.

## 5. 기획서 작성

`templates/business-plan.md`의 구조를 따라 `business-plan.md`를 작성한다.
- 첫 페이지 요약만으로 의사결정이 가능해야 한다.
- 세부 분석은 각 분석 파일을 요약 인용하고 링크한다.
- 수치는 분석 파일에 있는 것만 쓴다.

## 6. 마무리

사용자에게 다음을 짧게 보고한다: 권고(추진/조건부 추진/보류/중단), 핵심 근거 3개, 가장 큰 리스크 1개, 산출물 폴더 경로.
